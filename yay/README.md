# Yay! 交流マップ / レターマップ / 通話マップ

静的サイトです。ビルドやAPIキーは不要です。フォルダー内のファイルを同じ場所に置いたまま、`interaction.html` または `review.html` を開いてください（ブラウザーのCORS制限により、ローカルファイルで動作しない場合は静的ホスティングへ配置してください）。

## ファイル構成

- `interaction.html` — 交流マップ
- `interaction.js` — 交流マップ専用ロジック（既存の投稿タイムライン分析）
- `review.html` — レターマップ
- `review.js` — レターマップ専用ロジック（レビュー/レター分析）
- `call.html` / `call.js` — 通話マップ（公開タイムラインの通話参加者チェック）
- `style.css` — 共通デザイン

2つの機能はHTMLとJavaScriptを分離しています。上部ナビゲーションから相互に移動できます。

## レターマップのAPI

1. ユーザーIDまたはプロフィールURLを入力した場合:
   - `GET /v2/users/fresh/{user_id}` でプロフィールと `reviews_count` を取得
2. 投稿URLを入力した場合のみ:
   - `GET /v2/posts/{post_id}` で投稿者の `post.user.id` を取得
   - 投稿タイムラインは取得しません
3. 投稿URLからのユーザー特定:
   - 投稿APIが `404 not found` を返す場合、その投稿はフォロワー限定として扱い、投稿URLからの分析を中止します
   - その場合は、対象ユーザーのプロフィールURLまたはユーザーIDを入力するよう案内します
   - プロフィールURL/ユーザーIDからなら、投稿が非公開でもレビューAPIで取得できるレターを分析できます
4. レター一覧:
   - 最初: `GET /v1/users/reviews/{user_id}?number=50`
   - 続き: `GET /v1/users/reviews/{user_id}?from_id={oldest_review_id}&number=50`
   - `reviews[]` の `reviewer.id` ごとに件数を集計
   - `pinned_reviews[]` も確認し、通常ページとIDが重複した場合は二重計上しません
   - `reviews_count` は全体件数の目安・進捗表示に使用します

レターマップは `/v2/posts/user_timeline` を呼び出しません。レビューAPIのページを順番に取得し、次ページのカーソルにはそのページの最小 review ID を使用します。

## APIアクセス

匿名の公開GETリクエストを `https://proxy.cors.dev/` 経由で送信します。ログイン情報、Cookie、認証情報は送信しません。CORSリレーは第三者サービスのため、停止・制限・仕様変更の可能性があります。HTTP 429またはAPI応答内のレート制限を検出した場合は、共通API層が全機能を一時待機させ、待機後に同じリクエストを自動再開します。これはAPI側の制限を回避するものではありません。

公開APIから取得できる範囲のみを扱います。非公開情報やDMにはアクセスしません。

## 共通APIプロバイダー・キャッシュ

全ページで `yay-api.js` を各機能スクリプトより先に読み込み、`window.YayAPI.fetch()` を通じて公開GET APIを呼び出します。通信/CORS障害や中継サービスの5xx・不正なJSON応答時は、登録済みの中継プロバイダーへ切り替えます。成功したGET応答はブラウザー内メモリとLocalStorageに短時間キャッシュし、同一URLへの同時リクエストは1回にまとめます。タイムライン・いいね一覧・ユーザープロフィールでキャッシュ時間を調整しています。

**重要:** Yay! API本体のHTTP 429、または応答JSON内のレート制限エラーを検出した場合は、別プロバイダーへ切り替えて制限を回避しません。`Retry-After` を尊重して全体を待機させます。キャッシュはブラウザー単位で共有され、別端末・別ブラウザーとは共有されません。公開中継サービスの可用性・利用条件・CORS対応は変更される場合があります。

開発者コンソールから `YayAPI.status()` で現在のプロバイダー、直近の状態、キャッシュ件数、共通待機期限を確認できます。`YayAPI.clearCache()` でキャッシュを消去できます。


## レート制限時の案内と自動待機

Yay! APIがHTTP 429、またはJSON内のレート制限エラーを返した場合、すべての機能の取得を一時停止します。待機基準は最初5秒で、429を検出するたびに次の待機基準を5秒増やします。正常なAPI取得が1回成功するたびに1秒減らし、最低5秒を維持します。この調整は成功・失敗に応じて繰り返し、ページ再読み込み後もLocalStorageに保存した値を引き継ぎます。

レスポンスに `Retry-After` が含まれ、ブラウザーから読める場合は、適応型の待機基準より長いときにサーバー指定の時間を優先します。画面下部には平易な日本語で「アクセス制限で一時停止中」「自動再開までの時間」「次回の待機基準」を表示します。待機が終わると同じリクエストを自動で再開します。複数機能で同時に取得している場合も、共通の待機時間を共有します。別プロバイダーへの切り替えでYay!側の制限を回避することはしません。


## 通話マップ（`call.html` / `call.js`）

- ユーザーIDまたはプロフィールURLを入力し、`GET /v2/users/fresh/{user_id}` でプロフィールを取得します。
- 公開タイムラインを `GET /v2/posts/user_timeline?number=50&user_id={user_id}` で取得します。
- 次ページは `from_post_id={前ページの最小 post ID}&number=50&user_id={user_id}` で取得します。
- `post_type === "call"` の投稿だけを対象にし、`conference_call.conference_call_users[]` のユーザーを参加者として集計します。
- 同じ通話内で同じユーザーが重複していても1回として数えます。複数の通話に参加していれば、その通話数分を加算します。
- ノードを選択すると通話日時、通話ID、ジャンル/ゲーム、通話全体の時間、参加者数、APIが返した役割を確認できます。
- APIの `duration` は通話全体の長さです。個々のユーザーの実際の入退室時刻や発話時間を示すものではありません。
- 非公開タイムライン（`error_code: -363`）はAPIの応答に従って停止します。公開情報のみを使用し、ログインやDMへのアクセスは行いません。


## 総合交流ランキング（combined.html）

交流マップ・レターマップ・通話マップのイベント数をユーザーごとに合算し、Top 50を総合交流マップとして表示します。ノード選択で各ユーザーの内訳と取得できた記録を確認できます。
