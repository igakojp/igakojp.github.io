# Yay! 交流マップ / レターマップ

静的サイトです。ビルドやAPIキーは不要です。フォルダー内のファイルを同じ場所に置いたまま、`interaction.html` または `review.html` を開いてください（ブラウザーのCORS制限により、ローカルファイルで動作しない場合は静的ホスティングへ配置してください）。

## ファイル構成

- `interaction.html` — 交流マップ
- `interaction.js` — 交流マップ専用ロジック（既存の投稿タイムライン分析）
- `review.html` — レターマップ
- `review.js` — レターマップ専用ロジック（レビュー/レター分析）
- `style.css` — 共通デザイン

2つの機能はHTMLとJavaScriptを分離しています。上部ナビゲーションから相互に移動できます。

## レターマップのAPI

1. ユーザーIDまたはプロフィールURLを入力した場合:
   - `GET /v2/users/fresh/{user_id}` でプロフィールと `reviews_count` を取得
2. 投稿URLを入力した場合のみ:
   - `GET /v2/posts/{post_id}` で投稿者の `post.user.id` を取得
   - 投稿タイムラインは取得しません
3. 投稿URLからのユーザー特定:
   - 投稿APIが `404 not found` を返す場合、その投稿はフォロワー限定として扱い、投稿URLからの分析を中止します
   - その場合は、対象ユーザーのプロフィールURLまたはユーザーIDを入力するよう案内します
   - プロフィールURL/ユーザーIDからなら、投稿が非公開でもレビューAPIで取得できるレターを分析できます
4. レター一覧:
   - 最初: `GET /v1/users/reviews/{user_id}?number=50`
   - 続き: `GET /v1/users/reviews/{user_id}?from_id={oldest_review_id}&number=50`
   - `reviews[]` の `reviewer.id` ごとに件数を集計
   - `pinned_reviews[]` も確認し、通常ページとIDが重複した場合は二重計上しません
   - `reviews_count` は全体件数の目安・進捗表示に使用します

レターマップは `/v2/posts/user_timeline` を呼び出しません。レビューAPIのページを順番に取得し、次ページのカーソルにはそのページの最小 review ID を使用します。

## APIアクセス

匿名の公開GETリクエストを `https://proxy.cors.dev/` 経由で送信します。ログイン情報、Cookie、認証情報は送信しません。CORSリレーは第三者サービスのため、停止・制限・仕様変更の可能性があります。HTTP 429またはAPI応答内のレート制限を検出した場合は、その時点で分析を完全停止し、「これ以上取得できません」と表示します。自動待機・再試行は行いません。これはAPI側の制限を回避するものではありません。

公開APIから取得できる範囲のみを扱います。非公開情報やDMにはアクセスしません。
