# Yay! 交流マップ / レターマップ

静的サイトです。ビルドやAPIキーは不要です。フォルダー内のファイルを同じ場所に置いたまま、`interaction.html` または `review.html` を開いてください（ブラウザーのCORS制限により、ローカルファイルで動作しない場合は静的ホスティングへ配置してください）。

## ファイル構成

- `interaction.html` — 交流マップ
- `interaction.js` — 交流マップ専用ロジック（既存の投稿タイムライン分析）
- `review.html` — レターマップ
- `review.js` — レターマップ専用ロジック（レビュー/レター分析）
- `style.css` — 共通デザイン

2つの機能はHTMLとJavaScriptを分離しています。上部ナビゲーションから相互に移動できます。

## レターマップのAPI

1. ユーザーIDまたはプロフィールURLを入力した場合:
   - `GET /v2/users/fresh/{user_id}` でプロフィールと `reviews_count` を取得
2. 投稿URLを入力した場合のみ:
   - `GET /v2/posts/{post_id}` で投稿者の `post.user.id` を取得
   - 投稿タイムラインは取得しません
3. 投稿URLからのユーザー特定:
   - 投稿APIが `404 not found` を返す場合、その投稿はフォロワー限定として扱い、投稿URLからの分析を中止します
   - その場合は、対象ユーザーのプロフィールURLまたはユーザーIDを入力するよう案内します
   - プロフィールURL/ユーザーIDからなら、投稿が非公開でもレビューAPIで取得できるレターを分析できます
4. レター一覧:
   - 最初: `GET /v1/users/reviews/{user_id}?number=50`
   - 続き: `GET /v1/users/reviews/{user_id}?from_id={oldest_review_id}&number=50`
   - `reviews[]` の `reviewer.id` ごとに件数を集計
   - `pinned_reviews[]` も確認し、通常ページとIDが重複した場合は二重計上しません
   - `reviews_count` は全体件数の目安・進捗表示に使用します

レターマップは `/v2/posts/user_timeline` を呼び出しません。レビューAPIのページを順番に取得し、次ページのカーソルにはそのページの最小 review ID を使用します。

## APIアクセス

匿名の公開GETリクエストを `https://proxy.cors.dev/` 経由で送信します。ログイン情報、Cookie、認証情報は送信しません。CORSリレーは第三者サービスのため、停止・制限・仕様変更の可能性があります。HTTP 429またはAPI応答内のレート制限を検出した場合は、その時点で分析を完全停止し、「これ以上取得できません」と表示します。自動待機・再試行は行いません。これはAPI側の制限を回避するものではありません。

公開APIから取得できる範囲のみを扱います。非公開情報やDMにはアクセスしません。

## リーダーボード（`leaderboard.html` / `leaderboard.js`）— いいね参加版

投稿 https://yay.space/post/615227650 に「いいね」したユーザーが参加者になります（返信・メンションは不要）。いいねを外すと一覧からも外れます。

- 参加者の取得: `GET /v1/posts/615227650/likers`（`last_id` を `from_id` に渡して続きを取得。新しいユーザーが増えなくなったら終了）。60秒ごと（タブ表示中のみ）と「今すぐ更新」で再取得。
- ユーザーごとに1回だけ: `GET /v2/posts/user_timeline?number=1&user_id={id}`
  - `error_code: -363`（鍵アカウント等）→ 順位には入れず、一番下の「特定できないユーザー」に表示。名前とアイコンだけ `GET /v2/users/{id}`（公開プロフィール）から取得します。
  - 成功 → タイムライン内の `user` から名前・画像・フォロワー・投稿数などを使用。
  - フォロー数・登録日・ログイン連続など足りない項目がある場合だけ `GET /v2/users/{id}` を追加で呼びます。
- 順位に入るのは、タイムラインが見られるユーザーだけです。
- ミックスレベルの計算式は従来どおり。取得できなかった項目は0として計算し「＊」を付けます。
- 画像出力: 「開始ユーザー」を選ぶと、そのユーザーから順位が下へ10人（残りが少なければその人数）を、上が高く下が低い順でPNG保存。画像は明るいカード＋バー形式で、Yay!ロゴと制作者アカウントを入れています。
- データは保存しません。HTTP 429 / API内の429では処理を完全停止します（「今すぐ更新」で手動再開）。

## 自己紹介カード（`profile-card.html` / `profile-card.js`）

- ユーザー選択: 投稿URL（`GET /v2/posts/{id}` → `post.user.id`、404はフォロワー限定として案内）、プロフィールURL、ユーザーIDのいずれか。確認用に `GET /v2/users/fresh/{id}` の名前・アイコンを表示します。
- はめ込み式の配置（スマホのホーム画面のように）: 40pxのマス目に位置と大きさがはまり（「グリッドにはめる」で切替）、カードの外には出ません（余白24px）。回転は15°刻み、文字サイズは2刻み、ヘッダーは横幅いっぱいに固定。テーマ・背景の模様・アイコンの形・リングは、タイルから選んで決めます（色の細かい指定は折りたたみ内）。テーマを変えると、色を手で変えていない文字の色も読みやすい色に切り替わります。
- 自由な配置: 回転（ハンドル／スライダー、15°吸着）、中央・端へのスナップとガイド線、矢印キーの微調整、元に戻す／やり直し（Ctrl+Z）、パーツ一覧からの選択、タグ・箇条書きを1つずつ動かせる「バラバラにする」。
- キャンバス: ヘッダー・アイコン・名前も含め、すべてのパーツをドラッグで移動、ハンドルで拡大縮小（右・下の辺は横幅・縦幅のみ）。最前面/ひとつ前/ひとつ後ろ/最背面、複製、削除。
- 文字: 色・大きさ・太字・下線・取り消し線・アウトライン・フォント。画像追加、ペン、図形（四角・角丸・円・星・ハート・線）の塗りつぶし/アウトライン。
- タグはバッジ（角丸のラベル）で表示し、タグごとに丸い画像を付けられます（画像は端末内でのみ使用）。
- 自己紹介・タグ・好きなこと・苦手なこと・聞いてほしいことの入力は、キャンバス上の文字パーツになります。
- テーマ（5種＋色指定）、背景の模様、角の丸さ、ヘッダーの暗さ、アイコンの形、リング（単色/二重/グラデーション/なし・色・太さ）。
- PNG保存（制作者の表示は常に入り、Yay!ロゴは初期状態で入り、消すこともできます）。いいこと（○）・ダメなこと（×）・聞いてね（△）は項目ごとに記号を付けて表示し、タグは8個・各12文字、各項目は5個・各20文字、自己紹介は200文字までに制限しています。データは保存されません。

## 安全面（自己紹介カード）

- 個人情報チェック: 電話番号・メールアドレス・URL・SNSのIDらしき文字列・住所・学校名らしき文字列を検出すると、カードに反映せず、保存もできません（全角/半角や区切り文字は正規化して判定）。数字を漢数字で書くなど、意図的な回避までは検出できません。
- 画像を追加する前に、顔・制服・学校名・住所が分かる写真を避ける注意を表示します。
- 「自分のアカウントです」にチェックしないと、ユーザーを確認できません（本人確認まではできません）。
- Canvasの `roundRect` が無い古いSafari向けに `site.js` で補完し、ロゴは `ctx.filter` を使わずに白抜きしています。

## 自己紹介カード v2（人の追加・タググループ）

- 「自己紹介／いいこと／ダメなこと／聞いてね」の専用入力欄は廃止（普通の「文字」と同じため）。文字はパーツを選び「文字の内容」で編集します。
- タググループ: グループ数もタグ数も無制限。グループ名は自由（例:「○ いいこと」）。タグごとに画像、またはユーザー（アイコン＋名前）を入れられます。個人情報チェックは継続。
- ユーザーの追加: 「＋ユーザー」（単独パーツ）／タググループ内の「＋ユーザーを追加」。ユーザーID・プロフィールURL・投稿URLで指定するか、カードを作るアカウントのフォロワー一覧（`GET /v3/users/{id}/followers?number=50&from={next_page_value}`、最後までスクロールすると次の50件を読み込み）から選びます。名前とアイコンは公開プロフィールの値を使用。
- リサイズ修正: 以前は大きさの変更が移動のたびに掛け算されて文字が巨大化していました。いまはドラッグ開始時の大きさを基準に計算します。右辺＝折り返し幅、角＝全体の拡大縮小。

- フォロワー一覧の検索: 入力欄にID/URL以外（名前）を入れると、フォロワーを名前で絞り込みます（全角半角・大文字小文字は区別せず、スペース区切りは全部含む人）。まだ読み込んでいない分は、見つかるまで（最大約2000人分）自動で続きを読み込みます。

## いいねした人から探す（`likers.js`）

投稿 https://yay.space/post/615116972 にいいねした人を、名前で検索して選べる共通ダイアログです。`GET /v1/posts/615116972/likers`（`last_id` を `from_id` に渡して続きを取得）を使い、開くたびに読み直します（新しいいいねも反映）。名前を入れると、見つかるまで続きを自動で読み込みます（最大約40ページ）。
- レターマップ: 入力欄の下の「いいねした人から探す」で選ぶと、そのユーザーIDが入力欄に入ります（分析は自分で開始ボタンを押します）。
- 自己紹介カード: ユーザー追加ダイアログの「いいねした人から探す」から選ぶと、そのユーザーを追加できます。
